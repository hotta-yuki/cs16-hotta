- **調査結果の要約 1**:
  1. `python vscode/project1/kukei_ani_2000_200_400.py --help` や `python -c "print(123)"` が stderr なしで終了コード `1` で終了することを確認。

  3. Conda 環境内の `python` (および `cpython` などの混在パッケージ) の DLL 不整合が疑われたため、`conda install -n venv --force-reinstall python` を実行。
  4. 再インストール後、Python コマンドおよびスクリプトが正常に動作するようになったことを検証。
- **ユーザーの依頼 2**: `vscode\project1\kukei_ani_2000_200_400.py と vscode\project1\kukei_ani_1250_200_800.py の差異を示して`

  - `git diff --no-index` コマンドを用いて両ファイルを比較。
  - 差異は「デフォルトの溝形状パラメータ（幅、深さ、ピッチ）」および「時間刻み幅 `dt` の計算式」のみであることを特定。

## 4. 事実確認（ファクトチェック）
- Windows イベントログ (`Get-WinEvent`) にて `python.exe` が `python312.dll` の内部処理でアクセス違反により強制終了している事実を確認。
- `conda list -n venv` で `conda-forge` 由来の `cpython` と `defaults` 由来のパッケージが混在していたことを確認し、バイナリの再インストールが最も安全な修復方法と判断。
- `git diff --no-index` により、コード上の違いがデフォルトパラメータ値と `dt` の計算式（1/4されているか否か）に限定されていることを確認。
